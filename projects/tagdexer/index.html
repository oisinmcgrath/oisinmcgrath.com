tagdexer

Tag-based code navigation and append-only decision logging for any repo — find files by what they do, not where they live, and keep a record of why things were built the way they were.

Home GitHub

tagdexer gives every file in a repo a set of short labels — recorder, active, deprecated — and indexes them into a single file you can search from the command line. Next to it sits tracker.js, an append-only architectural decision log, so the next person to open the repo — or the next AI coding agent — doesn't have to rediscover the reasoning from scratch.

Use it when

A repo has grown past the point where folder names tell you where anything is, and full-text grep returns too much. Tags describe a file's role; the combination of tags is its fingerprint.

  • Search by role and status instead of guessing at directories
  • Schema-validated decision log — decision, intent, context, files affected
  • CLI-first, so it works with any coding agent and needs no editor
  • Optional VS Code / VSCodium sidebar for tag search and editing
  • Portable — copy the folder into any repo, or deploy in one click
  • Free software under the MIT licence

Source & full docs on GitHub

How it works

Tags are declared either as a header comment in the file's own syntax, or — for JSON, images and folders that can't carry comments — in a companion .tags file. The indexer scans the repo, resolves aliases so db and sqlite both find database, and writes a single .tagindex.json at the root. 

# in a source file
# @tagdex: recorder, online, active
node tagdexer/indexer.js --search "active,-deprecated"

Searches combine include and exclude terms, so you can ask for everything that is live without seeing the parts already on their way out.

Requirements

  • Node.js 22 or newer
  • ripgrep on your PATH
  • VSCodium or VS Code 1.85+ — only for the optional sidebar

The CLI is plain Node and cross-platform; it is developed and tested on Fedora Linux.
